# Linux.do Flip

Linux.do 的阅读进度 Tampermonkey 脚本。

它会读取最新主题列表，按照关键词和分类筛选主题，逐个打开并根据正文长度阅读。超长主题按楼层保存进度，不会因为单次时间用完或暂时滚到页面底部就被误判为已经读完。当前版本为 `1.7.0`。

## 功能

- 读取 `/latest.json`，请求失败或遇到 `429` 时限速重试；单次请求 20 秒无响应会主动中断并进入恢复
- 按主题标题包含词、排除词和分类名称、slug、ID 筛选
- 默认读取 180 个主题，自动扩展页数，最多支持 200 个主题
- 默认点赞目标 30 个；每 6 个完整读完的合格主题进入一次点赞审查
- 已读主题去重，最多保留最近 5000 条记录
- 分开保存“页面观察到的楼层”和“站点已确认记录的楼层”；断点续读以后者为准
- 每段阅读结束后重新读取主题 JSON 的 `last_read_post_number`，确认 Linux.do 已实际记录阅读进度
- 该核验确认的是 Discourse 已读楼层，不宣称 XP 或排行榜已经结算；若站点积分使用其他规则或存在延迟，需要以排行榜实际变化为准
- 区分“字段不存在”“字段存在但为空”和“服务端进度为 0”；首次打开尚未创建用户主题记录时会继续核验
- 核验请求使用禁用缓存的主题 JSON，避免一分钟内的旧响应被误当成新进度
- 服务端新响应与本地已核验楼层取较大值作为本段基线；较小或异常响应不能让可信断点倒退
- 站点进度没有增长时不会把本地滚动误记为有效阅读，也不会把主题标成完成
- 未完成主题即使服务端楼层等于本地观察楼层，只要相对本段起点没有增长，仍判定为无效；已经服务端确认完成的主题除外
- 站点确认字段缺失、核验请求失败或连续没有记录时显示明确诊断
- v1.6 之前只保存在本地、未经过服务端核验的楼层自动降为观察值，不直接作为可信续读断点
- 再次抽到未读完主题时，从上次楼层继续，不从第一楼重读
- 原生导航模式先翻主题列表，按页面实际出现顺序寻找合格未读话题，遇到第一个就点击
- 选中列表中先出现的候选后，会把它调到当前队列位置，而不是拿着预定标题在页面里定向寻找
- 页面位置和已核验楼层不一致时，以服务端确认进度作为断点；更靠后的页面楼层只记录为观察值
- 在列表中向下滚动加载、边翻边选帖；读完后通过浏览器历史返回列表并恢复原滚动位置
- 列表暂时没有合格候选时，按包含关键词进行宽泛搜索；未设置关键词时使用最新排序继续翻找
- 只有已经保存过阅读楼层或累计阅读时间的未完成主题，才允许按标题搜索并以 `topic_id` 精确恢复
- 新主题不会按明确标题检索；列表与宽泛搜索均无候选时安全暂停，不会偷偷直达预定话题
- 持久化记录列表、搜索、打开、阅读、返回和审查阶段，页面跳转后继续原步骤
- 阅读异常先自动重试当前主题两次；仍失败则保留已核验进度、移到队尾并继续其他主题
- 列表翻找或宽泛搜索失败时自动回到原列表重试两次，不会改成明确标题直达
- 新主题在“返回列表”阶段超时也只重试列表，不会沿用已选主题的直达恢复路径
- 全局连续故障达到 6 次，或当前没有其他可继续主题时安全暂停，避免无限恢复循环
- 恢复任务时审查队列，剔除无效项、重复项和已经完成的主题，不从头重建队列
- 监听 Linux.do 单页路由变化，点击真实链接后无需依赖整页刷新
- 提供“原生导航”和“直接续读”两种明确模式，由用户切换，不进行随机伪装
- 默认把帖间等待从原来的 7–15 秒缩短为 2–6 秒，并允许在面板自行设置 0–60 秒
- 默认只在页面处于前台时阅读和计时；切到后台后暂停，返回前台继续
- 阅读期间通过标准 Screen Wake Lock API 申请屏幕常亮；暂停、停止或切到后台时释放，返回前台或锁意外失效后重新申请
- 浏览器或系统不支持屏幕常亮时明确显示状态，不使用隐藏视频、循环音频等替代手段
- 单次阅读时间用完后把长帖排到队尾，稍后继续
- 长帖使用队列旋转而不是重复追加，读取多少段都不会让会话队列无限膨胀
- 完成前读取主题 JSON 审查总楼层；只有页面到达最后楼、底部稳定且服务端也确认到最后楼才记为已读
- 跨页面保存任务，刷新、跳转或脚本重启后仍能恢复
- 主题完成采用持久化两阶段提交：先保存 `pendingCompletion`，再提交已读、计数和点赞审查；两步之间崩溃会在重启后幂等补完
- 完成恢复会先确认旧主题是否仍在队列，再计算下一索引；队列审查已经移除旧主题时不会额外 `+1` 跳过下一帖
- 同一时间只允许一个标签页执行任务
- 同一标签页已有可恢复任务时再次点击“开始”不会覆盖原队列；需要重开必须先停止
- 支持暂停、继续、停止和清空已读记录
- 支持“重试当前”和“跳过当前”；跳过不会写入已读记录
- 面板显示当前阶段、队列位置、主题 ID、站点核验状态、连续故障数、恢复次数和上次错误
- 自动保存参数和面板位置
- 面板支持鼠标与触摸拖动、右下角连续缩放，并提供适合手机点击的“缩小 / 默认 / 放大”按钮
- 点击一次按 40px 宽、60px 高调整面板；达到屏幕边缘或最小尺寸后自动停止
- 手机横竖屏切换或窗口尺寸变化后，面板自动重新限制在可见区域
- 右下角触摸缩放区域由 22×22px 扩大为 38×38px；双击标题或点击“默认”恢复默认尺寸和位置
- 不进行随机或盲目自动点赞；候选完整读完并通过状态审查后暂停，必须手动点击“确认点赞并继续”
- 点击点赞后等待按钮状态或主题 JSON 确认；站点未确认时不增加点赞计数，也不会自动离开审查

## 安装

1. 浏览器安装 Tampermonkey。
2. 新建脚本。
3. 复制 `linuxdo_flip.user.js` 的完整内容并保存。
4. 打开 `https://linux.do/latest`。

## 参数

- **读取页数**：至少读取多少页；当主题数量较大时会自动增加，但最多读取 20 页。
- **本轮话题**：本轮最多读取多少个未读主题，默认 180，范围为 1–200。
- **点赞目标**：本轮最多确认多少个点赞，默认 30；这是上限，不保证所有候选都应点赞。
- **打开方式**：
  - `原生导航`：先翻主题列表，点击页面顺序中第一个符合筛选条件的未读话题；未完成长帖续读时才恢复明确主题。
  - `直接续读`：直接打开本地保存的最后楼层，适合列表无法加载目标主题时使用。
- **帖间最短/最长**：两个主题之间的等待区间，默认 2–6 秒，可设为 0–60 秒。
- **仅在页面前台时阅读和计时**：页面进入后台后停止阅读滚动、正文计时和帖间计时。
- **阅读时申请手机屏幕常亮**：使用浏览器标准 Wake Lock；实际是否生效仍取决于手机浏览器和系统权限。
- **最短停留**：正文很短时仍会停留的最低秒数。
- **单次最长**：一次连续阅读该主题的时间上限，不再代表主题已经完成。时间到后保存楼层并排到队尾续读。
- **基础速度**：每秒阅读字符数；每个主题会在该速度附近产生轻微变化。
- **包含关键词**：标题至少命中其中一个词；留空表示不限制。
- **排除关键词**：标题命中任意一个词就跳过。
- **分类**：支持分类名称、slug 或数字 ID，多个值用逗号或换行分隔。

## 状态规则

- 点击“暂停”后，脚本保留当前队列和位置；点击“继续”恢复。
- 暂停、停止、任务完成或页面转入后台时会释放屏幕常亮锁。
- 页面重新回到前台且任务仍在运行时，会再次申请屏幕常亮并从原进度继续。
- 点击“停止”后，本轮任务结束，当前未读完的主题不会写入已读记录。
- 页面异常或处理失败时先自动恢复，不会丢失队列或从头重建任务。
- 运行中误点“开始”只提示继续或停止，不会重新抓取主题覆盖正在执行的会话。
- 当前主题失败后按 1.5 秒、3 秒退避重试；第三次失败时保留站点已核验楼层并移到队尾。
- 列表或宽泛搜索故障会返回原列表重试；新主题仍不会通过明确标题或主题 URL 定向恢复。
- 连续故障达到 6 次、列表恢复超过 2 次，或只剩一个持续失败的主题时安全暂停。
- 每段结束后固定最多回读 3 次 `last_read_post_number`；字段暂时缺失也会继续尝试，只有站点进度增长或站点已确认整帖完成才算有效。
- 本地页面看到的楼层只作诊断；刷新、崩溃和自动恢复均从站点已经确认的楼层继续。
- 服务端核验完成但本地完成提交尚未结束时，重启会补写已读、完成计数和待点赞审查，不会直接把主题从队列剔除。
- “重试当前”会清除本次导航错误并重新定位当前主题。
- “跳过当前”只从本轮剩余队列移开当前主题，不会标记已读；下轮仍可再次抽到。
- 如果另一个 Linux.do 标签页正在运行任务，当前标签页不会同时启动第二份任务。
- 新主题按“列表翻找 → 宽泛搜索”的顺序选取，不做明确标题检索。
- 未完成长帖按“列表恢复 → 精确搜索核验 ID → `/last` → 服务端已核验楼层”的顺序续读。
- 列表、搜索、打开或返回状态超过 25 秒会触发分级恢复；超过各阶段上限后移队或安全暂停。
- 点赞候选会进入 `review` 状态。点击“确认点赞并继续”才会触发当前主题首帖的站内点赞按钮；点击“不点赞，继续”不会产生互动。
- 置顶、已点赞、关闭或归档主题不会进入点赞候选。
