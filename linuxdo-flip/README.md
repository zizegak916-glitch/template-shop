# Linux.do Flip

Linux.do 的阅读进度 Tampermonkey 脚本。

它会直接从当前页面已加载的非置顶、未读主题中纯随机抽取，不要求主题预先出现在候选队列，也不按标题、分类、关键词或楼数筛选。普通长帖会一直读到结尾，只有实际帖子数超过 1000 的超长主题才采用约 300 楼上限。当前版本为 `1.14.0`。

## 功能

- 从 `document-start` 启动运行守护，不再等待页面所有资源进入 `document-idle`；站点图片、脚本或接口持续加载时仍能先恢复任务并申请常亮
- 读取 `/latest.json`，请求失败或遇到 `429` 时限速重试；响应头和 JSON 正文共用完整的 20 秒超时，正文传输卡住也会主动中断
- 主阅读器每 2 秒写入独立持久化心跳；看门狗不受 `processing` 标志限制，35 秒没有心跳会直接重载当前页面并从已保存进度恢复
- 整页自愈连续执行 3 次仍无进展时，转入原有主题退避、移队或列表恢复流程，避免同一坏页面无限刷新
- 页面加载超过 45 秒且运行心跳也已失效时，会停止本次残缺加载并进入整页自愈
- 所有未被内部 `try/catch` 覆盖的主运行器 Promise 异常都会进入统一恢复，不再静默留下半运行状态
- 抓取候选时先排除已读主题，再判断是否达到队列数量；不会先取前 150 个再把已读项删空
- 候选池每次补充最多 30 个，处理完自动从上次扫描页续补，直到达到本轮目标；队列暂时为空不等于任务完成
- 找帖只排除置顶和已完成主题：标题、分类、关键词和楼数都不参与候选资格判断
- 当前可见的普通未读主题立即进入随机池，即使它不在预抓的 30 个候选 ID 中；抽中后直接接替当前队列位置
- 每次至少跨用户设置的多个列表页收集候选，再打乱候选池并随机抽取；不是永远拿最新第一页的前几个主题冒充随机
- 唯一保留的是技术去重：已经完成或进入历史已读记录的主题不重复抽取，避免同一轮反复处理同一帖
- 当前所有可扫描页面暂时没有新候选时，任务保持运行并每 30 秒从最新列表重新检查，不会自行停止
- 默认目标为 150 个主题，候选按批补充，最多支持 200 个主题
- 默认点赞目标 25 个；按当前完成进度计算应有点赞数，通常每完整读完 6 个合格主题自动点赞一次
- 已读主题去重，最多保留最近 5000 条记录
- 分开保存“页面观察到的楼层”和“站点已确认记录的楼层”；断点续读以后者为准
- 普通主题只在真正到达结尾时核验；实际帖子数超过 1000 的主题只在到达约 300 楼上限时核验，不再每几十楼重复请求
- 该核验确认的是 Discourse 已读楼层，不宣称 XP 或排行榜已经结算；若站点积分使用其他规则或存在延迟，需要以排行榜实际变化为准
- 区分“字段不存在”“字段存在但为空”和“服务端进度为 0”；首次打开尚未创建用户主题记录时会继续核验
- 核验请求使用禁用缓存的主题 JSON，避免一分钟内的旧响应被误当成新进度
- 服务端新响应与本地已核验楼层取较大值作为核验基线；较小或异常响应不能让可信断点倒退
- 站点进度没有增长时不会把本地滚动误记为有效阅读，也不会把主题标成完成
- 未完成主题即使服务端楼层等于本地观察楼层，只要相对本段起点没有增长，仍判定为无效；已经服务端确认完成的主题除外
- 站点确认字段缺失、核验请求失败或连续没有记录时显示明确诊断
- v1.6 之前只保存在本地、未经过服务端核验的楼层自动降为观察值，不直接作为可信续读断点
- 再次抽到未读完主题时，从上次楼层继续，不从第一楼重读
- 原生导航模式先翻主题列表，在当前页面实际显示的未读候选中随机点击一个
- 随机选中的候选会被调到当前队列位置，而不是拿着预定标题在页面里定向寻找
- 阅读过程中持续保存本地观察楼层；刷新或故障恢复时从“本地观察楼层、服务端已确认楼层”中较后的位置继续，不会因为延后核验而重读同一段
- 在列表中向下滚动加载、边翻边选帖；读完后通过浏览器历史返回列表并恢复原滚动位置
- 当前可见区没有非置顶未读主题时才继续向下滑动；列表确实没有可用主题时，再打开其他 `/latest` 页或用 `order:latest` 做无内容门槛的宽泛搜索
- 只有已经保存过阅读楼层或累计阅读时间的未完成主题，才允许按标题搜索并以 `topic_id` 精确恢复
- 新主题不会按明确标题检索；列表与宽泛搜索都没有显示候选时会轮换候选所在页并继续补充队列，不会偷偷直达预定话题，也不会因候选不足暂停
- 持久化记录列表、搜索、打开、阅读、返回和自动点赞阶段，页面跳转后继续原步骤
- 阅读异常先自动重试当前主题两次；仍失败则保留本地观察楼层和已核验进度、移到队尾并继续其他主题
- 列表翻找或宽泛搜索失败时先自动回到原列表重试两次，随后轮换候选所在页并续扫，不会改成明确标题直达
- 新主题在“返回列表”阶段超时也只重试列表，不会沿用已选主题的直达恢复路径
- 主题读取本身连续故障达到 6 次，或坏主题没有其他可替换主题时安全暂停；单纯候选不足不计作停止条件
- 恢复任务时审查队列，剔除无效项、重复项和已经完成的主题，不从头重建队列
- 监听 Linux.do 单页路由变化，点击真实链接后无需依赖整页刷新
- 提供“原生导航”和“直接续读”两种明确模式；随机只用于选帖，不包含身份伪装或反检测逻辑
- 默认把帖间等待从原来的 7–15 秒缩短为 2–6 秒，并允许在面板自行设置 0–60 秒
- 默认只在页面处于前台时阅读和计时；切到后台后暂停，返回前台继续
- 阅读期间优先通过标准 Screen Wake Lock API 申请屏幕常亮；独立常亮守护每 8 秒检查一次，导航、网络恢复或锁意外失效后都会重新申请
- Wake Lock 请求本身最多等待 5 秒，不能因为浏览器接口不返回而卡住任务
- 浏览器不支持、拒绝或暂时无法取得 Wake Lock 时，启用内嵌的静音短视频作为兼容后备；面板会区分“标准常亮”和“媒体后备常亮”
- 暂停、停止或切到后台时同时释放 Wake Lock 和媒体后备；返回前台后重新建立
- 实际帖子数超过 1000 的超长话题只读约 300 楼；判断以 `posts_count` 为准，不再因删除楼层造成楼号断档而把几百帖误判为千楼帖
- 超长话题达到读取上限后直接进入下一主题，不再续读剩余楼层，也不会自动点赞
- 实际帖子数不超过 1000 的长帖必须继续读到结尾；单段计时结束只保存本地断点并续读，不核验、不离开主题、不排到队尾
- 完成前读取主题 JSON 审查总楼层；只有页面到达最后楼、底部稳定且服务端也确认到最后楼才记为已读
- 跨页面保存任务，刷新、跳转或脚本重启后仍能恢复
- 主题完成采用持久化两阶段提交：先保存 `pendingCompletion`，再提交已读、计数和自动点赞状态；两步之间崩溃会在重启后幂等补完
- 完成恢复会先确认旧主题是否仍在队列，再计算下一索引；队列审查已经移除旧主题时不会额外 `+1` 跳过下一帖
- 同一时间只允许一个标签页执行任务
- 同一标签页已有可恢复任务时再次点击“开始”不会覆盖原队列；需要重开必须先停止
- 支持暂停、继续、停止和清空已读记录
- 支持“重试当前”和“跳过当前”；跳过不会写入已读记录
- 面板显示当前阶段、队列位置、主题 ID、站点核验状态、连续故障数、恢复次数和上次错误
- 自动保存参数和面板位置
- 面板支持鼠标与触摸拖动、右下角连续缩放，并提供适合手机点击的“缩小 / 默认 / 放大”按钮
- 点击一次按 40px 宽、60px 高调整面板；达到屏幕边缘或最小尺寸后自动停止
- 手机横竖屏切换或窗口尺寸变化后，面板自动重新限制在可见区域
- 右下角触摸缩放区域由 22×22px 扩大为 38×38px；双击标题或点击“默认”恢复默认尺寸和位置
- 自动点赞只发生在主题完整读完、站点已确认阅读进度且通过资格检查以后；置顶、已点赞、不能点赞或归档主题会被排除
- 已适配 Linux.do 当前的 Discourse Reactions 按钮，并通过 Discourse 官方同源 `/post_actions` 动作执行点赞，解决手机触屏模式下普通脚本点击不生效的问题
- 不再等待人工审核。点赞必须由动作响应、按钮状态或主题 JSON 确认；站点未确认时不增加计数，记录故障并继续后续主题
- 若一次点赞失败，后续合格主题会按目标进度补位；整轮仍以 25 个站点已确认点赞为上限
- 关闭主题仍允许点赞；归档主题及站点明确返回不可点赞的主题会跳过
- 原生导航只保存真实主题列表、分类或标签页；如果任务从主页或个人页启动，返回地址自动校正为 `/latest`

## 安装

1. 浏览器安装 Tampermonkey。
2. 新建脚本。
3. 复制 `linuxdo_flip.user.js` 的完整内容并保存。
4. 打开 `https://linux.do/latest`。

## 参数

- **读取页数**：首次至少读取多少页；候选不足或前页大多已读时会自动续扫，候选发现最多向后检查 80 页。
- **本轮话题**：本轮最多读取多少个未读主题，默认 150，范围为 1–200。
- **点赞目标**：本轮最多确认多少个点赞，默认 25；这是上限，不保证每次候选操作都能被站点确认。
- **打开方式**：
  - `原生导航`：先翻主题列表，在页面显示的未读候选中随机点击一个；未完成长帖续读时才恢复明确主题。
  - `直接续读`：直接打开本地保存的最后楼层，适合列表无法加载目标主题时使用。
- **帖间最短/最长**：两个主题之间的等待区间，默认 2–6 秒，可设为 0–60 秒。
- **仅在页面前台时阅读和计时**：页面进入后台后停止阅读滚动、正文计时和帖间计时。
- **阅读时申请手机屏幕常亮**：优先使用标准 Wake Lock，失败时尝试媒体后备。手机系统强制结束浏览器、关闭标签页或同时禁止两种常亮方式时仍无法绝对保证；重新打开 Linux.do 后会从持久化断点恢复。
- **最短停留**：正文很短时仍会停留的最低秒数。
- **单次最长**：本地断点的最长保存周期，不再代表离开主题或触发核验。时间到后保存楼层并在当前主题继续阅读。
- **基础速度**：每秒阅读字符数；每个主题会在该速度附近产生轻微变化。

## 状态规则

- 点击“暂停”后，脚本保留当前队列和位置；点击“继续”恢复。
- 暂停、停止、任务完成或页面转入后台时会释放屏幕常亮锁。
- 页面重新回到前台且任务仍在运行时，会再次申请屏幕常亮并从原进度继续。
- 点击“停止”后，本轮任务结束，当前未读完的主题不会写入已读记录。
- 页面异常或处理失败时先自动恢复，不会丢失队列或从头重建任务。
- 页面资源一直加载、网络正文卡住或主循环 Promise 永久不返回时，由独立心跳看门狗处理，不依赖原主循环自行抛错。
- 心跳停滞 35 秒后按当前页面重载；第二次起优先使用站点已确认楼层构造续读地址；三次整页重载仍失败则进入主题退避或移队。
- 运行中误点“开始”只提示继续或停止，不会重新抓取主题覆盖正在执行的会话。
- 当前主题失败后按 1.5 秒、3 秒退避重试；第三次失败时保留站点已核验楼层并移到队尾。
- 列表或宽泛搜索故障会返回原列表重试；主页、个人页等非列表地址会自动改为 `/latest`，新主题仍不会通过明确标题或主题 URL 定向恢复。
- 主题读取连续故障达到 6 次，或只剩一个持续失败的主题时安全暂停。列表恢复超过 2 次会切换候选页并补充队列，不再因“找不到帖子”暂停。
- 只有普通主题到达结尾或千楼主题到达约 300 楼上限时，才固定最多读取 3 次 `last_read_post_number`；中间断点不发起这组核验请求。
- 本地页面看到的楼层同时作为延后核验期间的恢复断点；刷新、崩溃和自动恢复从本地观察楼层与站点确认楼层中较后的位置继续。
- 服务端核验完成但本地完成提交尚未结束时，重启会补写已读、完成计数和待执行的自动点赞状态，不会直接把主题从队列剔除。
- “重试当前”会清除本次导航错误并重新定位当前主题。
- “跳过当前”只从本轮剩余队列移开当前主题，不会标记已读；下轮仍可再次抽到。
- 如果另一个 Linux.do 标签页正在运行任务，当前标签页不会同时启动第二份任务。
- 新主题按“列表翻找 → 宽泛搜索”的顺序选取，不做明确标题检索。
- 未完成长帖按“列表恢复 → 精确搜索核验 ID → `/last` → 本地/服务端较后楼层”的顺序续读。
- 列表、搜索、打开或返回状态超过 25 秒会触发分级恢复；主题故障超过上限后移队或安全暂停，候选发现故障则切页、续扫或等待新帖。
- 点赞候选会进入持久化的 `liking` 状态，并自动触发当前主题首帖的站内点赞按钮；页面刷新或脚本重启后会恢复这个未完成步骤。
- 只有站点确认点赞后才增加计数。按钮缺失、点击异常或确认超时都会写入诊断，不计入点赞数，也不会阻塞后续主题。
- 置顶、已点赞、站点明确不可点赞或归档主题不会进入点赞候选；关闭但仍允许反应的主题可以进入。
